## Voraussetzungen

- Node 20 oder neuer
- Postgres 14+ **oder** Redis 6+ als Speicher
- TypeScript 5.4+, falls du Typen willst (empfohlen, aber nicht Pflicht)

## Paket installieren

<Tabs items={['npm', 'pnpm', 'yarn', 'bun']}>
  <Tab value="npm">```bash npm install wisp ```</Tab>
  <Tab value="pnpm">```bash pnpm add wisp ```</Tab>
  <Tab value="yarn">```bash yarn add wisp ```</Tab>
  <Tab value="bun">```bash bun add wisp ```</Tab>
</Tabs>

Der Speicher-Adapter liegt getrennt, damit du nur den Treiber ziehst, den du
brauchst:

<Tabs items={['Postgres', 'Redis']}>

<Tab value="Postgres">

```bash
npm install @wisp/postgres
```

```ts title="wisp.config.ts"
import { defineConfig } from 'wisp';
import { postgres } from '@wisp/postgres';

export default defineConfig({
  speicher: postgres({ url: process.env.DATABASE_URL! }),
});
```

</Tab>

<Tab value="Redis">

```bash
npm install @wisp/redis
```

```ts title="wisp.config.ts"
import { defineConfig } from 'wisp';
import { redis } from '@wisp/redis';

export default defineConfig({
  speicher: redis({ url: process.env.REDIS_URL! }),
});
```

</Tab>

</Tabs>

<Callout title="Welcher Speicher?">
  Postgres, wenn du ohnehin eine Datenbank hast und Jobs zusammen mit deinen
  Daten sichern willst — die Job-Tabelle liegt dann in derselben Transaktion.
  Redis, wenn Durchsatz wichtiger ist als Haltbarkeit.
</Callout>

## Einrichten

<Steps>

<Step>
### Schema anlegen

Nur bei Postgres nötig. Redis braucht keine Vorbereitung.

```bash
npx wisp migrate
```

Das legt zwei Tabellen an: `wisp_jobs` und `wisp_leases`. Beide sind additiv,
spätere Versionen fügen nur Spalten hinzu.
</Step>

<Step>
### Ersten Job schreiben

```ts title="jobs/index.ts"
import { job } from 'wisp';

export const aufraeumen = job('aufraeumen', {
  async run() {
    await db.sitzungen.loescheAelterAls('30d');
  },
});
```
</Step>

<Step>
### Worker starten

```bash
npx wisp worker
```

Der Worker findet deine Jobs über `wisp.config.ts` und meldet beim Start, wie
viele er registriert hat:

```log
wisp  bereit — 1 Job registriert, Speicher: postgres
wisp  warte auf Arbeit (nebenläufig: 4)
```
</Step>

</Steps>

<Callout type="warn" title="Worker gehören nicht in den Webserver-Prozess">
  Ein Worker im selben Prozess wie dein HTTP-Server teilt sich dessen
  Ereignisschleife. Ein langsamer Job macht dann deine Requests langsam. Nimm
  einen eigenen Prozess oder Container.
</Callout>

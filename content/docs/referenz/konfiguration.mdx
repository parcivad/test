Wisp sucht `wisp.config.ts` im Projektwurzelverzeichnis. Ein anderer Ort geht
mit `--config`.

```ts title="wisp.config.ts"
import { defineConfig } from 'wisp';
import { postgres } from '@wisp/postgres';

export default defineConfig({
  speicher: postgres({ url: process.env.DATABASE_URL! }),
  jobs: './jobs/index.ts',
  nebenlaeufig: 8,
  aufbewahrung: { erledigt: '7d', gescheitert: '30d' },
});
```

## Dauerangaben

Überall, wo eine Dauer steht, geht beides:

```ts
zeitlimit: '90s'      // Zeichenkette mit Einheit
zeitlimit: 90_000     // Millisekunden als Zahl
```

Erlaubte Einheiten: `ms`, `s`, `m`, `h`, `d`. Kombinationen wie `'1h30m'`
funktionieren ebenfalls.

## Umgebungsvariablen

Sie haben Vorrang vor der Datei — praktisch, um denselben Container in zwei
Rollen zu starten.

| Variable | Entspricht |
|---|---|
| `WISP_NEBENLAEUFIG` | `nebenlaeufig` |
| `WISP_WARTESCHLANGEN` | `warteschlangen` (kommagetrennt) |
| `WISP_PACHTDAUER` | `pachtdauer` |
| `WISP_PROTOKOLL` | `protokoll` |
| `WISP_METRIK_PORT` | Port für den Metrik-Endpunkt |

```bash
# derselbe Container, zwei Rollen
WISP_WARTESCHLANGEN=standard WISP_NEBENLAEUFIG=16 npx wisp worker
WISP_WARTESCHLANGEN=berichte WISP_NEBENLAEUFIG=2  npx wisp worker
```

<Callout type="warn" title="Pool und Nebenläufigkeit gehören zusammen">
  Ist `poolGroesse` kleiner als `nebenlaeufig`, warten deine Jobs auf
  Verbindungen statt auf Arbeit. Das sieht in den Metriken wie ein langsamer
  Job aus, ist aber ein zu kleiner Pool.

## Mehrere Umgebungen

`defineConfig` nimmt auch eine Funktion:

```ts
export default defineConfig(({ umgebung }) => ({
  speicher: postgres({ url: process.env.DATABASE_URL! }),
  nebenlaeufig: umgebung === 'produktion' ? 16 : 2,
  protokoll: umgebung === 'produktion' ? 'normal' : 'ausführlich',
}));
```

`umgebung` kommt aus `NODE_ENV` und ist `'entwicklung'`, wenn nichts gesetzt
ist.

Ein Job ist eine benannte Funktion plus die Regeln, unter denen sie ausgeführt
wird.

```ts
import { job } from 'wisp';

export const bericht = job('monatsbericht', {
  wiederholungen: 3,
  zeitlimit: '5m',
  warteschlange: 'berichte',
  async run({ monat }: { monat: string }, ctx) {
    ctx.log(`baue Bericht für ${monat}`);
    return await berichte.baue(monat);
  },
});
```

Der erste Parameter ist der **Name**. Er steht im Speicher und im Protokoll und
darf sich nicht ändern, solange noch Jobs dieses Namens eingereiht sind.

<Callout type="warn" title="Umbenennen ist ein Bruch">
  Wisp ordnet eingereihte Arbeit über den Namen zu. Benennst du einen Job um,
  während noch alte Einträge warten, findet der Worker keine passende Funktion
  mehr und meldet `unbekannter_job`. Lass den alten Namen eine Weile als Alias
  stehen.
</Callout>

## Die Nutzlast

Alles, was `enqueue()` bekommt, wird als JSON gespeichert. Daraus folgen zwei
Regeln.

### Klein halten

Die Nutzlast wird bei jedem Versuch gelesen und geschrieben. Ein Bild gehört
nicht hinein — seine Kennung schon.

```ts
// nein
await bildUmrechnen.enqueue({ bytes: buffer });

// ja
await bildUmrechnen.enqueue({ bildId: '7c2e' });
```

### Nur serialisierbares

`Date`, `Map`, `Set` und Klassen-Instanzen überleben die Runde nicht. Wisp
warnt beim Einreihen, wenn es etwas findet, das nach dem Serialisieren anders
aussieht als davor.

<Callout title="Datumsangaben">
  Nimm ISO-Zeichenketten. `new Date()` kommt als Zeichenkette wieder heraus,
  und der Typ verspricht dir etwas anderes.
</Callout>

## Idempotenz

Ein Job kann mehr als einmal laufen — bei einer Wiederholung, oder wenn ein
Worker stirbt, nachdem die Arbeit getan, aber bevor sie bestätigt wurde.
Schreib ihn so, dass ein zweiter Lauf nichts kaputt macht.

```ts
export const rechnungStellen = job('rechnung-stellen', {
  // gleicher Schlüssel → höchstens ein wartender Eintrag
  schluessel: ({ bestellungId }) => `rechnung:${bestellungId}`,

  async run({ bestellungId }: { bestellungId: string }) {
    const vorhanden = await db.rechnungen.finde({ bestellungId });
    if (vorhanden) return vorhanden;           // zweiter Lauf: nichts tun

    return await db.rechnungen.erstelle({ bestellungId });
  },
});
```

Der `schluessel` verhindert **Doppel-Einträge**, die Prüfung in `run()`
verhindert **Doppel-Wirkung**. Beides braucht es; keines ersetzt das andere.

## Der Kontext

Das zweite Argument von `run()`:

      description: 'Wird ausgelöst, wenn das Zeitlimit greift oder der Worker herunterfährt.',
      type: 'AbortSignal',
    },

Reich `ctx.signal` an alles weiter, was lange dauert — sonst läuft deine
Anfrage weiter, obwohl Wisp den Versuch längst abgeschrieben hat:

```ts
async run({ url }: { url: string }, ctx) {
  const antwort = await fetch(url, { signal: ctx.signal });
  return await antwort.json();
}
```

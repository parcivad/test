Wisp nimmt Arbeit entgegen, die nicht im Request-Zyklus erledigt werden soll:
Mails verschicken, Bilder umrechnen, nächtliche Berichte bauen. Du schreibst
eine gewöhnliche Funktion, Wisp kümmert sich um Reihenfolge, Wiederholungen
und darum, dass nichts zweimal läuft.

```ts title="jobs/willkommensmail.ts"
import { job } from 'wisp';

export const willkommensmail = job('willkommensmail', {
  async run({ nutzerId }: { nutzerId: string }) {
    const nutzer = await db.nutzer.find(nutzerId);
    await mail.send(nutzer.email, 'willkommen');
  },
});

// irgendwo im Anwendungscode
await willkommensmail.enqueue({ nutzerId: '42' });
```

Mehr braucht es nicht. Kein Scheduler-Objekt, das herumgereicht wird, keine
separate Registrierung — der Aufruf von `job()` ist die Registrierung.

## Was Wisp zusagt

- **Genau-einmal je Versuch.** Ein Job, der abstürzt, wird wiederholt — aber
  kein Versuch läuft doppelt parallel. Details unter
  [Warteschlangen](/docs/konzepte/warteschlangen).
- **Typen bleiben erhalten.** Die Nutzlast von `enqueue()` hat denselben Typ
  wie der Parameter von `run()`. Kein `any` dazwischen.
- **Keine eigene Infrastruktur nötig.** Als Speicher genügt die Postgres- oder
  Redis-Instanz, die du ohnehin hast.

<Callout title="Was Wisp nicht ist">
  Kein Message-Broker und kein Workflow-Motor. Wenn du fächernde Abläufe mit
  Verzweigungen und Kompensationsschritten brauchst, ist Wisp die falsche
  Ebene — es führt einzelne Funktionen zuverlässig aus, mehr nicht.
</Callout>

## Aufbau in einem Bild

```text
  Anwendung            Speicher              Worker
      │                    │                    │
      ├─ enqueue() ───────►│  Job liegt bereit  │
      │                    │◄─ hol dir Arbeit ──┤
      │                    ├─ Job + Pacht ─────►│
      │                    │                    ├─ run()
      │                    │◄─ fertig ──────────┤
      │                    │                    │
      │                    │◄─ hol dir Arbeit ──┤  ⟲
```

Die **Pacht** ist der Kern: Ein Worker hält einen Job nur für eine begrenzte
Zeit. Stirbt er, läuft die Pacht ab und ein anderer Worker übernimmt.
